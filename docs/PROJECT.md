# QStock — база знаний проекта

> Единый источник правды о проекте. Обновляется при **каждом** изменении:
> перед пушем/PR сюда записывается, что сделано, как работает и как настраивается.
> Порядок работы описан в скиле `.claude/skills/project-knowledge/SKILL.md`.

## 1. Что это

QStock — внутренняя система отдела **BR (Brand Retail)** для сети розничных точек
IQOS/TEREA в Узбекистане. Решает: учёт остатков и продаж по сменам на каждой
торговой точке, контроль честности открытия/закрытия смен (гео + фото),
инвентаризации, расчёт закупа, контроль визитов саппорта. Валюта — сум,
интерфейс — русский.

## 2. Роли и их сценарии

| Роль | Кто это | Основные экраны |
|------|---------|-----------------|
| **SE** (Sales Expert) | Продавец на точке | Моя смена, Поступление, Инвентаризация, Заметки, История смен |
| **BRE** (в UI — **Support Exec**) | Куратор своих точек | Остатки (дашборд критичных остатков), Аналитика, Мои точки, Смены, Визиты в точки, Инвентаризации, График инвентаризаций, Закуп |
| **ADMIN** | Администратор | Всё: Дашборд, Аналитика, Точки, Смены, Визиты, Инвентаризации, Закуп, SKU, Пользователи, Планы инвентаризаций, Журнал действий |

Ключевые правила взаимодействия:
- SE подключается к **одной** точке (лимит `points.max_se`); закрытие смены отключает всех SE от точки.
- Смена — общая на точку (не на человека). Закрыть может любой подключённый SE; если закрыл не тот, кто открывал — ставится флаг `closed_by_other` (аудит-аномалия, не блокировка).
- BRE видит и правит **только свои** точки (`points.bre_id`); все его правки логируются в аудит.
- Саппорт может как техпомощь: открыть/закрыть смену точки, править утренние остатки, задавать минимумы точки — из монитора точки (панель «Действия саппорта»).

## 3. Функции (что и как работает)

### Смены
- Открытие: перенос остатков со вчера (`carryover`) или ручной ввод. Для SE **обязательное фото с камеры** (модалка getUserMedia, фолбэк — системная камера через `<input capture>`) и геолокация (не блокирует: отказ → пометка «без геолокации»). Координаты пишутся в `shifts.open_lat/lng`.
- Закрытие: сводка → для SE обязательное фото + гео (`close_lat/lng`). Саппорт/админ закрывают без камеры (техпомощь, удалённо).
- Гео-контроль: если у точки заданы `lat/lng`, в мониторе и деталях смены показывается «✓ на точке» или «⚠ N м/км от точки» + ссылка на карту.
- **Пересменка**: если смену открывает SE, отличный от закрывшего предыдущую, ставится `needs_inventory=1` — закрытие заблокировано до инвентаризации. Тот же SE открывает свободно.
- Продажи вносятся как накопительный итог «продано» (set-sales, дельта пишется в `sales`), списания — аналогично. Формула остатка: `opening + income − sales_qty − writeoff (+ adjust)`.

### Поступление и накладные
- Экран «Поступление»: количества по SKU + до 5 **фото накладных** (камера или файл; сжатие на клиенте до 1280px JPEG). Фото уходят в `attachments (kind='invoice')` вместе с `income-batch`.

### Минимальные остатки
- Глобальный минимум у SKU (`skus.min_stock`) + **индивидуальный по точке** (`point_sku_min`). Везде действует эффективный минимум `COALESCE(point, global)`: дашборды, монитор, /lowstock, аналитика, уведомления. Правка — кнопка «Минимумы точки» в мониторе (админ и BRE своих точек), пустое поле = глобальный.

### Визиты Support Exec
- Старт: монитор точки → «Визит в точку», или раздел «Визиты в точки» → «Новый визит» (выбор среди точек с открытой сменой).
- Сверка: по каждому SKU системный остаток против фактического; совпадение → `confirmed`, расхождение подсвечивается. Плюс комментарий, гео, фото.
- Отчёты в разделе «Визиты в точки» (BRE — свои, админ — все) с фильтром по точке; расхождения шлют уведомление `visit_mismatch` всем админам (realtime + бейдж на пункте меню «Визиты в точки»).

### Прочее
- Инвентаризации: назначение (саппорт/админ/график `inventory_schedules`), проведение SE, результат перезаписывает opening; история с расхождениями.
- Закуп: расчёт по фактическим продажам (`per_day × (horizon + lead) × (1+safety%)`), у SKU свои safety/lead (`sku_logistics`), Excel-экспорт.
- Фото-галерея: «Фото смены» в мониторе/деталях (открытие, закрытие, накладные), фото визита в деталях визита.
- Уведомления: `low_stock`, `shift_overdue`, `inventory_assigned/done`, `visit_mismatch` — колокольчик + realtime toast.
- Excel: отчёт смены, заявка на заказ, закуп (`server/xlsx.js`, без зависимостей).
- Тёмная/светлая тема, мобильная вёрстка (нижняя навигация ≤760px).

## 4. Архитектура

```
server/
  index.js      — Express + Socket.IO, маршруты, JSON limit 10mb (фото data-URL)
  db.js         — node:sqlite DatabaseSync, схема + лёгкие миграции addColumn()
  auth.js       — JWT (cookie qstoken или Bearer), requireRole
  access.js     — visiblePointIds / canSeePoint / seConnected
  stock.js      — currentStock-обвязка, effMinStock, checkLowStock (уведомления)
  realtime.js   — комнаты Socket.IO: emitPoint / emitUser / emitAll
  scheduler.js  — крон внутри процесса: просроченные смены, график инвентаризаций
  bootstrap.js  — демо-сид при пустой БД
  xlsx.js       — генерация .xlsx вручную (zip+xml)
  routes/       — users, skus, points, shifts, inventory, analytics, notes,
                  attachments, visits, misc (dashboard, lowstock, procurement,
                  movements, notifications, audit)
public/
  index.html, styles.css, app.js — SPA на ванильном JS, роутер в renderRoute(),
  realtime-обновления через App._refresh, все тексты русские
tests/
  run.js — интеграционные API-тесты (98 проверок), ui.js — Playwright (33)
```

### БД (главные таблицы)
`users` (role SE/BRE/ADMIN, status), `points` (bre_id, max_se, lat/lng, канал, СПВ),
`point_se` (подключения SE), `skus` (+min_stock), `sku_logistics`, `point_sku_min`,
`shifts` (status, needs_inventory, closed_by_other, open/close_lat/lng),
`shift_stock` (opening/income/sales_qty/writeoff/adjust), `sales`, `movements`,
`inventories`+`inventory_items`, `inventory_schedules`, `attachments`
(kind: invoice|shift_open|shift_close|visit; data = data-URL), `visits`+`visit_checks`,
`notifications`, `audit_log`, `notes`, `price_history`.

### Realtime-события
`stock:update`, `sale:new`, `shift:changed`, `point:changed`, `sku:changed`,
`notes:changed`, `notification` (персонально). Клиент подписывается `watch:point`.

## 5. Настройка и запуск

```bash
npm install
npm start                  # PORT=3000, БД data/qstock.db
PORT=3010 DB_PATH=data/dev.db node server/index.js   # свои порт/БД
```
Переменные: `PORT`, `DB_PATH`, `JWT_SECRET` (обязательно задать в проде).
Демо-логины после сида: `admin/admin123`, `bre/bre123`, `se/se123`, `se2/se123`, `bre2/bre123`.

**Деплой**: Render, сервис `qstock`, автодеплой из ветки **`final-project`**
(`render.yaml`). Секреты — только в Render Dashboard, не в репозитории.

**Тесты** (сервер и тесты запускать в одном вызове, тестовые БД `data/test-*.db` удалять):
```bash
PORT=3010 DB_PATH=data/test-api.db node server/index.js &  sleep 1.5
BASE=http://localhost:3010 node tests/run.js    # 98 API-проверок
PORT=3012 DB_PATH=data/test-ui.db node server/index.js &   sleep 1.5
BASE=http://localhost:3012 node tests/ui.js     # 33 UI-проверки (Playwright)
```
UI-тесты используют фейковую камеру/гео: chromium с
`--use-fake-ui-for-media-stream --use-fake-device-for-media-stream`,
permissions `camera`+`geolocation`. Бинарь chromium: `/opt/pw-browsers/chromium`.

## 6. Соглашения разработки

- Рабочая ветка — **только `final-project`**. Старые ветки — архив, не трогать.
- Команды в терминале — через `rtk` (см. CLAUDE.md).
- Перед пушем: полный прогон API+UI тестов, всё зелёное.
- Любое изменение → запись в «Журнал изменений» ниже (этот файл коммитится вместе с кодом).
- Миграции БД — только добавляющие (`CREATE TABLE IF NOT EXISTS`, `addColumn`), совместимые со старой БД на Render.
- Фото — только клиентски сжатые data-URL (~1280px JPEG); обязательность фото — на фронте для SE, сервер принимает и без фото (техпомощь саппорта, API-тесты).
