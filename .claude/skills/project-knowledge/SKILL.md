# Работа с базой знаний QStock

Единый источник правды о проекте — **`docs/PROJECT.md`**. Он описывает роли,
функции, архитектуру, схему БД, запуск/настройку, соглашения и журнал изменений.

## Правила (обязательные)

1. **Перед началом любой задачи** — прочитай `docs/PROJECT.md`, чтобы понять
   контекст, соглашения и не сломать существующие сценарии ролей.

2. **Перед каждым коммитом/PR/пушем** — обнови `docs/PROJECT.md` тем же коммитом:
   - добавь строку в таблицу «7. Журнал изменений» (дата, коммит, что сделано);
   - если изменились функции, роли, схема БД, API, настройка или соглашения —
     обнови соответствующие разделы (1–6), чтобы описание совпадало с кодом;
   - пиши по-русски, кратко и конкретно: что добавлено/изменено, как работает,
     как настраивается.

3. **Никогда не пушь код без записи в журнал.** Если правка чисто техническая
   (опечатка, форматирование) — всё равно одна строка в журнал.

4. Соглашения проекта (дублируются в PROJECT.md, раздел 6): работать только в
   ветке `final-project`; перед пушем полный прогон `tests/run.js` (API) и
   `tests/ui.js` (Playwright) — всё зелёное; миграции БД только добавляющие;
   команды через `rtk`.
